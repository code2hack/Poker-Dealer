# Fold6 M3 Dealer state-recovery evidence — 2026-07-31

## Scope

This records the real Fold6 process-death and reboot checks for GitHub issue #30. Dealer used its
production encrypted host-profile storage, Room attachment/draft stores, private no-backup recovery
files, embedded tailnet, SSH, proxy WebSocket, and app-server session stack. Wireless ADB was used
only to inspect state, deliver `SIGKILL`, reboot Android, and explicitly relaunch Dealer.

Private addresses, host pins, credentials, thread IDs, thread content, process IDs, and concrete
app-server endpoints are omitted. A standalone Tailscale connection carried diagnostic ADB after
reboot; Dealer's Spark session used Dealer's separate embedded userspace tailnet route.

## Tested device and build

- Samsung SM-F956N (Fold6), Android 16, build `BP4A.251205.006`.
- Dealer `0.1.0-m1`, debug APK SHA-256
  `ee0b1c8a986eb21034bed72ab51d174f54a5f640514bccb4efc02a94643a7a69`.
- DGX Spark was the only workstation backend used. u4090 was unavailable and excluded from all
  build, test, artifact, CI, and fallback work.
- The APK's native AAR was regenerated by the committed amd64 Docker builder running locally on
  ARM64 Spark. No remote artifact-production fallback was used.

## Prepared durable state

Dealer connected to Spark through `SSH_EMBEDDED_TSNET`. One existing Spark thread was attached, an
exact diagnostic draft was stored, and Dealer held soft control before the destructive check. The
private Room database contained one attachment, one draft, and zero pending thread actions.

The recovery projection and pending-request snapshots existed beneath Dealer's private
`no_backup` directory. No private recovery data was placed in public storage.

## Process-death check and defect found

Dealer was backgrounded and its application process received a raw `SIGKILL`; Android package
force-stop was not used. The process remained absent for five seconds, the package stopped flag
remained clear, and hashes of the durable private state did not change. Dealer was then relaunched
explicitly.

That first run exposed a real recovery defect: the enabled Spark intent was restored, but the
embedded tailnet was left stopped, so the restored session entered backoff with the embedded route
reported disabled. `DealerConnectionService` restored sessions without restarting the route they
required.

The fix reuses the stored host profile and starts the embedded node during service recovery only
when an enabled host has a configured tailnet route, before starting host sessions. It adds no boot
receiver and does not start the node for LAN-only or loopback-only profiles.

After rebuilding and installing the APK in place, the raw `SIGKILL` sequence was repeated. The
explicit cold launch automatically moved the embedded node to connected and restored the Spark
session through `SSH_EMBEDDED_TSNET`, without a Start or Connect tap. The attachment and exact draft
remained present, pending thread actions remained zero, and recovered soft control was `NONE`.

## Reboot check

ADB rebooted the real Fold6. After Android reported boot complete, the kernel boot identifier was
different from the pre-reboot value. Before launching Dealer:

- Dealer had no process;
- Dealer had no active notification;
- the package stopped flag was clear; and
- Dealer's private recovery, database, profile, and credential files remained present.

The standalone Tailscale app was disconnected after reboot. Local-Wi-Fi wireless ADB was used only
to capture the time-sensitive no-autostart observations and reconnect that app. ADB was then
reconnected to the new wireless-debugging port through the Fold6 tailnet endpoint, and the absence
of a Dealer process and notification was confirmed again before launch.

Dealer was explicitly cold-launched over that tailnet ADB connection. Without a Start or Connect
tap, its embedded node reached connected and the Spark session restored through
`SSH_EMBEDDED_TSNET`. Post-reboot private-state inspection found:

- one attached thread;
- the one exact diagnostic draft;
- zero pending thread actions;
- one attached recovered projection with intended control surface `NONE`; and
- no recovered pending command, file, or structured-user-input request.

The UI exposed `Detach` and `Take control`, confirming the attachment and soft-control reset. The
only active Dealer notification was foreground-service notification ID 4090; no attention or ready
notification was synthesized during recovery.

## Limits

- The live run covered one Spark thread, one attachment, and one draft.
- No live in-flight command, file, structured-user-input request, or accepted turn action was
  interrupted across process death or reboot. The no-replay result is therefore automated
  fail-closed coverage plus observation of zero live pending actions, not a real-device in-flight
  replay proof.
- The Fold6 was awake for interactive observation. This is not a long-duration Doze, OEM-kill, or
  battery-life claim.
- This evidence does not complete issue #30's integration dependencies on issues #22 and #28.
